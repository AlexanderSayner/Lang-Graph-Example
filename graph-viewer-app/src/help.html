LangGraph Studio Documentation

Welcome to the visual builder for LangGraph. This guide will help you construct complex agentic workflows using GraphQL mutations.

Core Concepts

  • Nodes: Processing units (Actions, Routers, Human inputs).
  • Edges: Connections between nodes. Can be conditional.
  • Subgraphs: Nodes that link to another entire graph, allowing for modular design.

Routing & Conditions

To create a "Router" (a decision point):

  1. Drag an Action Node (e.g., intent_router).
  2. Connect it to multiple targets.
  3. Click the connection lines and add Conditions (e.g., intent == 'billing').
  4. The Action Node will automatically become a Router if it has conditional outputs.

Best Practices

  • Router Prompts: Instruct the LLM to output JSON that matches your edge conditions.
    Example Prompt: "Extract 'intent'. Output JSON like {'intent': 'billing'}."
  • Human Nodes: Always place a Human Node after asking a question. This ensures the graph pauses and waits for the user's answer before continuing.
  • Loops: Connect a node back to a previous Router to create a loop (e.g., "Ask for clarification -> Router").

Advanced Example: The "Smart Dealership"

This example demonstrates a tiered architecture:

  1. Main Graph: A router that directs traffic to Sales or Support.
  2. Sales Subgraph: A conversational bot that ensures specific car models are captured before confirming a sale.

Step 1: Build the "Sales Worker" Subgraph

This graph handles the logic of asking for a car model and confirming the purchase. It loops back if the user changes their mind.

GraphQL Subgraph 
mutation BuildSalesWorker {
  buildGraph(
    input: {
      graphId: "dealership-sales-v1"
      graphName: "Sales Negotiation Worker"
      nodes: [
        { nodeId: "sales_start", nodeType: "START", handlerName: "salesStartHandler" }
        {
          nodeId: "ask_model",
          nodeType: "ACTION",
          handlerName: "askModelHandler",
          metadata: {
            system_prompt: "You are a car sales expert. If the user mentions only a brand (e.g., 'Honda'), ask for the specific model (e.g., 'Accord'). If they provide a model, acknowledge it."
          }
        }
        { nodeId: "wait_model", nodeType: "HUMAN", handlerName: "waitModel" }
        {
          nodeId: "confirm_deal",
          nodeType: "ACTION",
          handlerName: "confirmDealHandler",
          metadata: {
            system_prompt: "If the user confirms the purchase, thank them. If they want to change the model, acknowledge that."
          }
        }
        { nodeId: "wait_confirmation", nodeType: "HUMAN", handlerName: "waitConfirm" }
        {
          nodeId: "check_done",
          nodeType: "ACTION",
          handlerName: "checkDoneHandler",
          metadata: {
            system_prompt: "Analyze the last message. If the user agrees/confirmed, output JSON: {\"decision\": \"done\"}. If they want to change/other intent, output JSON: {\"decision\": \"change\"}. Output ONLY JSON."
          }
        }
        {
          nodeId: "finalize_sale",
          nodeType: "END",
          handlerName: "finalizeHandler",
          metadata: { system_prompt: "Congratulate the user on their new car." }
        }
      ],
      edges: [
        { source: "sales_start", target: "ask_model" },
        { source: "ask_model", target: "wait_model" },
        { source: "wait_model", target: "confirm_deal" },
        { source: "confirm_deal", target: "wait_confirmation" },
        { source: "wait_confirmation", target: "check_done" },

        # Loop back if user wants to change model
        { source: "check_done", target: "ask_model", condition: "decision == 'change'" },

        # Finish if done
        { source: "check_done", target: "finalize_sale", condition: "decision == 'done'" }
      ]
    }
  ) {
    success
    graphId
  }
}

Step 2: Build the Main "Manager" Graph

This graph acts as the entry point. It routes to the Sales Subgraph or a Support node.

GraphQL Parent Graph 
mutation BuildManager {
  buildGraph(
    input: {
      graphId: "dealership-main-v1"
      graphName: "Dealership Orchestrator"
      nodes: [
        { nodeId: "entry", nodeType: "START", handlerName: "entryHandler" }
        {
          nodeId: "intent_router",
          nodeType: "ACTION",
          handlerName: "routerHandler",
          metadata: {
            system_prompt: "Analyze intent. If user wants to buy/car -> 'sales'. If help/issue -> 'support'. Output JSON: {\"intent\": \"sales\"}."
          }
        }

        # THE SUBGRAPH NODE
        {
          nodeId: "handle_sales",
          nodeType: "GRAPH",
          handlerName: "salesSubgraphHandler",
          metadata: {
            subgraph_id: "dealership-sales-v1" # Links to the graph built in Step 1
          }
        }

        {
          nodeId: "handle_support",
          nodeType: "END",
          handlerName: "supportHandler",
          metadata: { system_prompt: "Connecting you to a support agent..." }
        }
      ],
      edges: [
        { source: "entry", target: "intent_router" },

        # Conditional Routing
        { source: "intent_router", target: "handle_sales", condition: "intent == 'sales'" },
        { source: "intent_router", target: "handle_support", condition: "intent == 'support'" }
      ]
    }
  ) {
    success
  }
}

Example 2: Context-Aware Router (Mood Reader)

This example builds a "Smart Assistant" that doesn't just route based on topic, but also analyzes the user's mood. This metadata is passed down to the subgraphs so the AI can adjust its tone (e.g., being extra polite if the user is angry).

Architecture

  • Parent Graph: Analyzes intent and mood. Routes to Subgraphs.
  • Subgraphs: Receive the variables object containing the mood and act accordingly.

Step 1: The Parent Graph (Mood Analyzer)

GraphQL AI Routing 
mutation BuildMoodRouter {
  buildGraph(
    input: {
      graphId: "mood-router-main-v1"
      graphName: "Sentiment Analysis Router"
      nodes: [
        { nodeId: "entry", nodeType: "START", handlerName: "entryHandler" }
        {
          nodeId: "mood_reader",
          nodeType: "ACTION",
          handlerName: "moodReaderHandler",
          metadata: {
            system_prompt: "Analyze the user input. Determine: 1. 'intent' ('chat' or 'q&a'). 2. 'mood' ('happy', 'angry', 'neutral'). Output ONLY JSON: {\"intent\": \"chat\", \"mood\": \"happy\"}."
          }
        }

        # Reference your existing Chat Graph
        {
          nodeId: "chat_subgraph",
          nodeType: "GRAPH",
          handlerName: "chatSubHandler",
          metadata: { subgraph_id: "graph-1779111595004" }
        }

        # Reference your existing Q&A Graph
        {
          nodeId: "qa_subgraph",
          nodeType: "GRAPH",
          handlerName: "qaSubHandler",
          metadata: { subgraph_id: "graph-1779111557381" }
        }

        { nodeId: "end_chat", nodeType: "END", handlerName: "endChat" }
        { nodeId: "end_qa", nodeType: "END", handlerName: "endQa" }
      ],
      edges: [
        { source: "entry", target: "mood_reader" },

        # Route based on Intent extracted by Mood Reader
        { source: "mood_reader", target: "chat_subgraph", condition: "intent == 'chat'" },
        { source: "mood_reader", target: "qa_subgraph", condition: "intent == 'q&a'" },

        { source: "chat_subgraph", target: "end_chat" },
        { source: "qa_subgraph", target: "end_qa" }
      ]
    }
  ) {
    success
  }
}

Note: The subgraphs defined in your previous steps will automatically receive the mood variable in their state. You can update their System Prompts to: "The user is currently {mood}. Adjust your tone accordingly."

🎨 Prefer Visual Building?

You don't have to write code to build these graphs! LangGraph Studio includes a fully interactive Visual Builder.

How to use the UI Builder

  1. Navigate to the Graph List on the main dashboard.
  2. Click the "+ New" button in the sidebar.
  3. Drag and Drop nodes from the left palette onto the canvas:
    • 🚀 Start: The entry point of your graph.
    • 🤖 Action: Standard AI processing nodes.
    • 👤 Human: Pauses execution for user input (Human-in-the-loop).
    • 🧩 Graph: Embeds an existing subgraph.
    • 🛑 End: The termination point.
  4. Connect nodes by dragging from the bottom handle of one to the top handle of another.
  5. Click any node to edit its ID, System Prompt, or select a Subgraph ID (for Graph nodes).
  6. Click "Save Graph" when finished.

The Visual Builder is perfect for prototyping flows rapidly before exporting them to code.
